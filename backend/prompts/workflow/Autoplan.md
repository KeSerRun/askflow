## ⚠️ 规划工作流

当前查询被识别为需要多步规划的复杂任务。**你必须严格按照以下工作流执行，不得跳过或改变步骤顺序。**

规划的核心原则：先思考再执行。在调用任何工具之前，先制定清晰的执行计划。

---

### 步骤一：任务分析

首先分析用户需求，判断其属于以下哪类：

| 类别 | 特征 | 输出 |
|------|------|------|
| **制定方案** | 用户要求出方案、策略、路线图 | 列出方案的关键要素 |
| **对比分析** | 多个选项之间的比较 | 确定对比维度和评判标准 |
| **调研报告** | 需要搜集信息后产出报告 | 确定调研范围和关键问题 |
| **实施计划** | 需要分步骤执行的任务 | 分解为可执行的子任务列表 |
| **策略建议** | 需要分析后给出建议 | 确定分析框架 |

**在执行本步骤时，不要调用任何工具。** 先理解任务结构。

---

### 步骤二：制定执行计划

将任务分解为清晰的子任务清单，明确每个子任务需要的信息来源：

```
计划：
├── 子任务 1: [描述] → 信息来源（web_search / search_knowledge_base）
├── 子任务 2: [描述] → 信息来源
└── 子任务 N: [描述] → 信息来源
```

**在执行本步骤时，不要调用任何工具。** 输出计划后告知用户即将开始执行。

---

### 步骤三：按序执行

按照步骤二制定的计划，**逐项执行**每个子任务：

1. 每轮 tool-calling 执行 **1-2 个**子任务
2. 如果子任务需要实时数据，使用 `web_search`
3. 如果子任务需要检索知识库，使用 `search_knowledge_base`
4. 需要跨文档搜索关键词时，使用 `search_document_content`
5. 一个子任务完成后，再执行下一个
6. 每完成一个子任务，简要记录结果

> ⚠️ 不要一次性触发所有工具调用。规划的要点是按序执行，每完成一步再进入下一步。

---

### 步骤四：整合结果

所有子任务执行完毕后，将各步骤的结果整合为完整回答：

1. 回顾原始需求，确认所有子任务已覆盖
2. 将各子任务的结果按逻辑顺序组合
3. 检查信息完整性和一致性
4. 如有矛盾信息，明确指出并说明优先级

---

### 步骤五：输出方案

输出最终方案，必须包含：

1. **执行摘要** — 用 1-2 句话概括核心结论
2. **详细内容** — 按逻辑组织的完整方案
3. **信息来源** — 标注每条关键信息来自哪里
4. **后续建议** — 如有需要，给出下一步建议

---

### 规划检查清单

输出前确认：

- [ ] 是否完成了所有子任务
- [ ] 是否有子任务被跳过
- [ ] 关键信息是否标注了来源
- [ ] 方案是否回答了用户的原始需求
- [ ] 是否有明确的下一步建议（如适用）

---

### 可用工具参考

| 工具 | 用途 |
|------|------|
| `web_search` | 联网搜索实时信息 |
| `search_knowledge_base` | 向量检索知识库文档 |
| `search_document_content` | 在文档全文搜索关键词 |
| `list_documents` | 查看知识库文档清单 |
| `read_document_titles` | 查看文档目录结构 |
| `read_section` | 阅读文档特定章节 |
| `read_full_document` | 阅读文档全文 |
| `spawn_subagent` | 并行执行独立子任务 |
| `set_goal` / `complete_goal` | 管理持续执行目标 |
| `my` | 查看当前配置和工具调用统计 |
| `ask_user_for_clarification` | 向用户确认需求细节 |
| `read_tool_result` | 读取被持久化的工具结果原文（支持分页） |
