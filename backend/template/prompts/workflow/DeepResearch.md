## ⚠️ 深度调研工作流

当前查询被识别为需要深度调研的复杂任务。**必须严格按以下步骤执行，不得跳过、合并或改变顺序。**

> **输出格式要求：** 向用户报告进度时，使用工作流中原始的三级标题格式 `### 步骤N：标题`。
>
> **勾选节奏：** 每完成一个步骤就**立即** `check_todo(id)` 勾选该项；**同一轮回复最多只勾 1 项**，禁止攒到最后一起勾。

---

### 步骤一：解析调研主题

明确：**核心主题**（用户想了解什么）、**调研维度**（背景/现状/趋势/争议/数据）、**广度 vs 深度**。同时把调研流程拆成 **3-6 项**并调用 `set_todolist` 发布（每项唯一 `id`，本工作流各步骤即清单项；**最后一项固定为「生成 PDF 交付物」**）。分析完成后进入下一步。

---

### 步骤二：多角度初步搜索

使用 `web_search` 按子维度搜索，**最多 3–5 个角度**，覆盖主要维度即停：

1. 主题概况 — 定义与基本事实
2. 最新动态 — 最近半年到一年的新闻/发展
3. 不同视角 — 正反/流派观点
4. 数据支撑 — 统计、报告、排名

> 若用户附了截图/图表，先 `ocr_image` 读出其中文字，纳入检索关键词。完成后进入下一步。

---

### 步骤三：深入阅读关键文章

从搜索结果挑 **1–3 篇**最有价值文章用 `read_url` 读全文（优先权威信源）。提取关键信息后进入下一步。

---

### 步骤四：检索知识库

`search_knowledge_base` **至少发起一次**，用多个角度 query（主题术语、行业关键词、新发现概念；`mode` 可选 `['image']` 找库里图片）。可用 `search_document_content` 全文定位。命中文档需要完整内容时用 `read_knowledge_base_document`。完成后进入下一步。

---

### 步骤五：信息交叉验证

检查：**信息矛盾**（标注并说明哪个更可靠）、**信息缺口**（明确告知）、**时效性**（标注数据时间点）。发现关键缺失可补充搜索/阅读一次。**每完成一步就即时勾选该项（同一轮最多勾 1 项）**。完成后进入下一步。

---

### 步骤六：输出结构化调研报告

1. **核心结论** — 2-3 句总结
2. **背景概述** — 让未接触者能理解
3. **分维度详述** — 每维独立成节，含数据、引用、来源
4. **争议与不同观点** — 客观呈现
5. **信息缺口** — 明确说明
6. **参考来源** — 文章标题 + URL

数据/引用行内标注来源（`[来源：文章标题]`）；关键数据用表格；长报告加目录导航。

---

### 步骤七：生成 PDF 交付物

把本次调研成文为**研究报告** PDF 并推送到对话（用户在对话里可直接下载）：

1. 先调用 `list_deliverable_templates` 看清可用模板与字段（研究报告 = `research_report`）。
2. 调用 `create_deliverable(template="research_report", title="<报告标题>", content={...})`，按下列字段组织内容：

   | 字段 | 填入内容 |
   |------|----------|
   | `summary` | 摘要：2-3 句核心结论 |
   | `background` | 研究背景（让未接触者能理解） |
   | `method` | 研究方法（检索信源类型 / 覆盖范围） |
   | `findings` | 主要发现：`[{"title": "...", "detail": "..."}]`，每个维度一条，含关键数据与来源标注 |
   | `conclusion` | 结论 |
   | `references` | 参考来源：`["文章标题 — URL", ...]` |

3. 字段文本**支持 Markdown**（`##` 小标题 / `-` 列表 / `**加粗**` / 表格），会自动渲染进 PDF。
   注意：小节大标题由模板生成，字段里**不要再写一级/二级标题**，直接从正文或三级小标题写起。
4. 内容要精炼（PDF 不是把对话内容整段抄一遍）；同一轮只勾 1 项，完成后 `check_todo` 勾选「生成 PDF 交付物」，再用 1-2 句告知用户「已生成《…》PDF，可直接下载」，**不要**在回答里重复整篇报告。

---

### 步骤八：完整性检查

`check_todo` 全部勾选完成后，最终输出前确认：

- [ ] 覆盖各调研维度
- [ ] 关键数据标注来源
- [ ] 矛盾与缺口如实说明
- [ ] 回答用户核心问题
- [ ] **PDF 交付物已生成**（对话里出现可下载的交付物卡片）
- [ ] Markdown 格式正确
